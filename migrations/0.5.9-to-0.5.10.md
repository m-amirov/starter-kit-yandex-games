# Starter Kit 0.5.9 → 0.5.10

Version 0.5.10 promotes release failures observed in production Yandex Games work into reusable Starter Kit contracts.

## Mature-project update

1. Update the Starter Kit source and run the canonical updater in `--dry-run` mode first.
2. Review semantic changes explicitly. In particular, `config/yandex-doc-snapshot.json` is now semantics-aware so a snapshot accepted through the supported docs-review command can remain clean without pretending to be immutable managed content.
3. Apply the update and run:
   - `npm run starter-kit:status`
   - `npm run starter-kit:self-test`
   - `npm run yandex:sdk:validate`
   - `npm run yandex:contract:validate`
   - `npm run yandex:requirements:audit`
   - `npm run yandex:console:audit`
4. Do not rewrite project-owned runtime, `index.html`, `game-spec.yaml`, narrative, assets or local release evidence as part of the updater itself. New validators may expose stale project declarations or SDK bootstrap defects; fix those as bounded project changes after the infrastructure update.

## New release barriers

- Production HTML must expose the official `/sdk.js` bootstrap before application modules; SDK initialization remains single-init and production-fail-closed.
- Mutable release declarations are checked against explicit release evidence rather than silently trusted.
- Finish source/config changes, commit and push `FINAL_RELEASE_HEAD`, then stop committing and generate HEAD-bound runtime/art/media evidence against that exact HEAD.
- First-publication gameplay videos are bound to the source HEAD and final file hash, include explicit opening-frame review, and require distinct media for localized gameplay text.

No Draft upload, moderation submission or publication is performed by this migration.
