# Migration 0.5.3: profile-aware quality constitution

## Scope

Starter Kit 0.5.3 materializes profile-dependent references inside managed
text files. `docs/QUALITY_CONSTITUTION.md` now uses the target profile's
configured `skillRoot`:

- `new-project` receives `.codex/skills/...` links;
- `mature-yandex-phaser` receives `.agents/skills/...` links.

The updater has no profile-name special case. The manifest explicitly marks
the document with `contentTemplate: true`, and both target-path and content
materialization use the same validated profile values.

## Mature-project transition

A 0.4.1 mature target may record `managed:quality-constitution` as a semantic
acceptance. If its existing `.agents/skills/...` document already matches the
0.5.3 materialized bytes, the updater promotes it to the managed baseline
without overwriting the file or reporting a managed conflict. The obsolete
semantic acceptance is removed from state.

If the project changed any other content in this document, the normal managed
drift policy still applies; no local content is silently replaced.

## Verification

Run an explicit mature dry run, apply only after reviewing unrelated semantic
conflicts, then repeat the dry run and status checks. The resulting project
must contain only its configured skill root and must keep product-owned files
unchanged.
