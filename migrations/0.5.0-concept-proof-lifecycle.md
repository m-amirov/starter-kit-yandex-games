# Migration 0.4.2 → 0.5.0 — Concept Proof Lifecycle

Version 0.5.0 adds a mandatory product-development lifecycle before production.

## Added

- managed Concept Proof Gate and first-prototype complexity budget;
- blind-playtest templates and explicit owner decision;
- production barrier before concept proof approval;
- project-termination workflow for an explicit `STOP_PROJECT`;
- UI test-harness adjudication contract;
- silent-execution and token-economy assertions.

## Mature-project update

Run the updater with the reviewed mature profile. Managed files update through
their recorded baseline. Existing `AGENTS.md` and same-name skills remain
semantic merges and require explicit resolution. Product runtime, content,
package lock, `index.html`, and `game-spec.yaml` remain project-owned.

After update, review `CONCEPT_PROOF_GATE.md`, preserve project-specific policy
in the project-owned contract zone, and run Starter Kit status plus a repeated
dry run to prove idempotency.

If a managed file has intentional pre-update drift that is fully represented
in 0.5.0, review the generated proposal and explicitly replace that one file
through `--resolve-managed <logical-id>`. This option is limited to files with
an existing managed baseline and never resolves semantic or project-owned files.
