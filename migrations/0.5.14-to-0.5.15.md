# 0.5.14 → 0.5.15: optional wardrobe visual acceptance for narrative games

- New reusable `WARDROBE_VISUAL_ACCEPTANCE_V1` adds independent original/runtime
  portrait and landscape pixel checks, character reference comparison, scene
  continuity and rationalized wardrobe changes/reuse.
- Existing narrative-game profiles remain disabled unless users explicitly
  opt in. New `wardrobeVisualAcceptance.enabled` defaults to false even when
  the narrative model is enabled; it does not launch browser turns.
- Starter Kit delivers `tools/production-art/wardrobe-visual-gate.mjs` and
  `docs/WARDROBE_VISUAL_ACCEPTANCE.md` using baseline-safe managed files.
- Projects with custom wardrobe validators should compare semantics before
  activating; no project-owned art, source HEAD, receipts or production
  mappings are overwritten.
- No Yandex SDK or runtime changes, no new CEOS-run requirement, no release
  automatic PASS and no retroactive invalidation of accepted production PNGs.
- This optional verifier needs a real independent reviewer response. A local
  brief check alone cannot establish visual acceptance.

## Activation after update

Copy `config/optional-profiles/narrative-game.json` to a project-owned local
profile and opt in explicitly with `enabled:true` and
`wardrobeVisualAcceptance.enabled:true`. See
`docs/WARDROBE_VISUAL_ACCEPTANCE.md` for request schema and CLI use.
