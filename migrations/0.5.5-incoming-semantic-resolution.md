# Starter Kit 0.5.5: incoming semantic resolution

`--resolve-semantic <logical-id>` continues to accept and record the current
project version of a semantic conflict.

Use `--resolve-semantic-incoming <logical-id>` only after explicit review when
the incoming Starter Kit version should replace the conflicting semantic or
target-mapped target. The updater materializes the incoming bytes through the
active target profile, records the materialized hash, and removes the matching
conflict proposal. `package.json` remains accept-current only so project
scripts and dependencies stay authoritative.
