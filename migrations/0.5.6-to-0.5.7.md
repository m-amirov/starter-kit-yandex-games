# Starter Kit 0.5.6 → 0.5.7

Version 0.5.7 adds the pinned `hardened-draft-runtime-harness-1.3.0` as an optional advisory post-upload Draft evidence provider. The validated manifest and six-file runtime closure are delivered as managed release tooling, byte-for-byte; historical provenance inputs, live reports, profiles, and product runtime are not delivered.

## Mature-project update

1. Start from a clean worktree and run `node tools/starter-kit/apply-update.mjs --target <project> --profile mature-yandex-phaser --dry-run`.
2. Review only the managed provider tooling, registry/schema, commands, docs, skills, and policy changes. Resolve existing semantic contracts through the normal explicit updater flow.
3. Apply the update, run `npm run yandex:external:verify`, then the full updater and Starter Kit self-tests.
4. Keep `game-spec.yaml`, `src/`, `public/`, `index.html`, product runtime, project evidence, browser profiles, local configuration, product assets, and package lock project-owned. The update creates no live evidence seed and no second skill root.

The update is idempotent after its managed baselines are recorded. It does not run an authenticated browser, publish evidence, build a game release ZIP, upload a Draft, or submit to moderation.

## Operational split

`yandex:docs:check` remains the authoritative-document freshness gate. `yandex:external:verify` validates only the external provider pin. Before final submission, run the authoritative validation first; after Draft upload, explicitly run the pinned provider when available, normalize its local-sensitive reports, and pass the normalized evidence to the independent release audit.

If any runtimeClosure byte differs from its validated raw SHA-256, stop with `ESCALATE_PROVIDER_PIN_INVALIDATED`; never rewrite the manifest hashes to fit changed files.
