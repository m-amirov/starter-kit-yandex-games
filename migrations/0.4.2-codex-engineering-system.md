# Migration 0.4.2 — Codex Engineering System and Token Economy

Version 0.4.2 makes `codex-engineering-system` an explicit Starter Kit engineering layer instead of relying on partial behavior embedded only in `$implementation-cycle`.

## Added

- mandatory `$codex-engineering-system` orchestration skill;
- managed `.starter-kit/core/CODEX_ENGINEERING_SYSTEM.md` contract;
- relevant-only skill and context loading;
- compact `.loop/` checkpoints;
- lowest-sufficient reasoning policy;
- targeted verification ladder and one-time barrier suites;
- fresh-evidence reuse rules;
- bounded retries and concise log handling;
- self-test coverage for the system and token-economy contract.

## Mature-project behavior

The skill is delivered through the configured `skillRoot`. An existing same-name skill uses semantic merge and is never overwritten blindly. The managed core contract is updated only through the normal baseline-aware updater. A second active skill root remains forbidden.

This infrastructure must remain separate from product runtime, assets, save schema, build output, and the Yandex release ZIP.

## Required review after update

1. Resolve any semantic proposal for `AGENTS.md` or an existing `codex-engineering-system` skill.
2. Confirm that project-specific protected areas remain in `PROJECT_RULES.md`.
3. Run `npm run starter-kit:self-test` and `npm run test:updater`.
4. During development, use targeted checks; reserve full platform and release suites for the appropriate barrier.
