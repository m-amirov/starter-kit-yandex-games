# Migration 0.3.0 — Full Yandex Games Requirements Gate

This migration is required for projects created with starter kit versions earlier than 0.3.0.

## Why it is not fully automatic

Files such as `game-spec.yaml`, `src/main.ts`, `src/styles.css`, game scenes, layouts, generated assets, and product E2E tests are project-owned. The updater deliberately does not overwrite them. Version 0.3.0 installs the reusable guard, layout registry, requirements registry, audits, skills, and generic moderation tests, but the project must integrate the project-owned touchpoints below.

## Required project changes

### 1. Upgrade `game-spec.yaml`

Compare the project file with the 0.3.0 seed and add:

- truthful Yandex categories and a rationale for each category;
- supported desktop/mobile platforms and orientation policy;
- startup language auto-detection through `ysdk.environment.i18n.lang`;
- responsive viewport matrix and both orientation transition directions;
- interaction guard requirements;
- maximum unpacked size of 100 MB or less;
- platform-feature applicability flags;
- content-duration, rights, marketing-media, and metadata review requirements.

Do not replace project-specific mechanics, identifiers, content, balance, or art direction.

### 2. Install browser interaction guards

In the game entry point call:

```ts
import { installInteractionGuards } from './starter-kit/browser/installInteractionGuards';

installInteractionGuards();
```

The game surface must prevent context menus, text selection, and native drag behavior on desktop and mobile. Native text inputs must remain usable.

### 3. Add CSS interaction protection

Apply equivalent rules to the document and game surface:

```css
html, body, #app, canvas {
  overflow: hidden;
  overscroll-behavior: none;
  touch-action: none;
  user-select: none;
  -webkit-user-select: none;
  -webkit-touch-callout: none;
}
```

Adapt selectors to the project. Do not disable text selection inside legitimate input, textarea, select, or contenteditable controls.

### 4. Make layouts resize-driven

- Recalculate positions and sizes after every viewport resize.
- Test portrait → landscape → portrait and landscape → portrait → landscape without reload.
- Ensure critical UI and gameplay objects remain inside the visual viewport.
- Prevent browser scroll, pull-to-refresh, clipping, and forbidden overlap.
- Register critical elements with `src/starter-kit/qa/layoutRegistry.ts`, or provide an equivalent QA bridge consumed by the moderation E2E tests.

### 5. Use SDK language at startup

Read and normalize `ysdk.environment.i18n.lang` after SDK initialization and before final startup UI is rendered. Verify RU and EN production flows.

### 6. Prove genre/category accuracy

Create `artifacts/evidence/genre-category-review.json` using the template. Categories must describe the actual playable loop, not merely visual objects shown in the game.

### 7. Create requirement evidence

Generate the compliance skeleton:

```bash
npm run yandex:requirements:init
```

Complete all applicable clauses and provide the required evidence files. Then run:

```bash
npm run yandex:requirements:audit
```

### 8. Run moderation regressions

The generic test `tests/e2e/yandex-moderation.spec.ts` must pass in Chromium, Firefox, and WebKit across the configured viewport matrix. Keep project-specific assertions for every screen and gameplay state that can be reached by users.

## Completion barrier

This migration is complete only when:

- `npm run starter-kit:status` is clean;
- `npm run yandex:requirements:audit` is PASS;
- context menu and selection tests pass on desktop and mobile emulation;
- both orientation-transition directions pass without clipping or overlap;
- category review and all applicable requirement evidence are complete;
- full `npm run rc` passes.

Record completion in the project changelog or engineering log. Do not use `--accept-local-conflicts` as a substitute for completing this migration.
