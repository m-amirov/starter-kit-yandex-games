# Migration 0.5.0 → 0.5.1 — Screenshot Visual Gate

Version 0.5.1 adds canonical `SCREENSHOT_VISUAL_GATE` as a mandatory acceptance barrier for production-visible work.

## Added

- current-HEAD actual-runtime screenshot evidence and impact-based state matrix;
- desktop plus real-touch mobile proof for gameplay/UI changes;
- visual review against project-owned art contracts and accepted baseline;
- an explicit block on implementation, acceptance, owner-review, visual and product completion tokens while required screenshot review is absent or fails;
- the reusable compact review template at `templates/visual-review/SCREENSHOT_VISUAL_GATE.md`.

## Mature-project update

Run the normal updater with the reviewed profile. Managed core/policy/template files update from their baseline. Existing `AGENTS.md`, same-name skills, and project-owned visual rules stay semantic/project-owned: review proposals, preserve stricter local requirements, manually merge only where necessary, then record each explicit semantic resolution. Do not copy managed infrastructure by hand and do not waive managed drift without `--resolve-managed` for that one reviewed baseline file.

The updater is idempotent after conflicts are resolved. It never modifies product runtime, `index.html`, `game-spec.yaml`, assets, or project-owned visual content. Add a short project-specific extension only where the game's art language, state matrix, or accepted baseline needs stricter rules.
